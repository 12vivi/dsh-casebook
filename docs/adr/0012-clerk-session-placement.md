# 0012 书记员会话挂在游戏会话下面，不自动起标题

## 背景

M0 发现：插件开的后台会话会出现在左侧会话列表里，玩家能点进去发消息；DSH 还会用会话绑定的模型给它起标题，多一次付费调用。

## 决定

- 书记员会话的标识是 `casebook-clerk-<游戏会话标识>`，建会话时写 `parentSession` 指向游戏会话、`origin` 标为 `subagent`。左侧列表里只出现游戏会话。
- 给书记员的消息用 `casebook` 来源，不用 `user` 来源。DSH 只拿 `user` 来源的消息起标题，所以书记员会话不会触发起标题的模型调用；插件直接把它改名为「书记员 · 案名」。
- 游戏会话开局时由插件改名为「雾港案卷 · 案名」。用户来源的标题会钉住，DSH 不再调模型改标题。
- 叙事每轮追加的案情资料也用 `casebook` 来源。聊天界面不把这类上下文显示成对话行，玩家看不到资料里的 L2 内容。

## 后果

- 这里的 `origin: 'subagent'` 只用来归类展示：书记员不经过 DSH 的子 Agent 注册表，由插件自己创建和恢复。
- 重启后书记员会话从存档恢复（`ctx.agents.resume`），接着用原来的上下文。
