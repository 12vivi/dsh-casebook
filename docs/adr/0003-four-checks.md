# 0003 游戏状态只能经过结算提议修改，程序做四道校验

## 背景

模型会记错、会编造、会把上一轮的事当成这一轮的。如果让模型直接改状态，线索板很快就会和正文对不上。

## 决定

游戏状态只有程序能写。书记员只能调用 `submit_effects` 提议这一轮的变化：行动类别、移动、发现的线索、态度变化、口供，每一项都要引用正文原句。程序依次做四道校验（`packages/domain/src/game/effects.ts`）：

1. schema：字段和取值合法（态度一次只能变 1，列表有上限）。
2. 规则：对象存在；发现、态度、口供只能发生在本轮场景（出发地加本轮移动到的地点）；前置线索已发现（同一次提交里先发现的也算）；证词线索的说话人态度达标（同一次提交里先改的态度也算）；态度不超出范围。
3. 版本：只能结算当前分支最新、还没有结论的那一版正文。
4. 原句：引用去掉空白和标点后至少 4 个字，并且在那一版正文里连续出现。

整批全部通过才原子写入；任何一项不通过就整批驳回，把规则和原句的错误一起交还给书记员改正。版本过期的提议直接作废，不用再改。同一版最多驳回 3 次。

## 后果

- 每一道都有该拦和不该拦的单测（`packages/domain/test/settlement.test.ts`）。
- 驳回也写进事件日志（`settlement/rejected`），以后评测可以统计书记员的出错率。
