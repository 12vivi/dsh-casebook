# 0002 正文先提交，派生结算随后

## 背景

dsh-tavern 的 ADR 0004 曾把「正文 + 后台结算」做成原子提交，后台偶发失败会连带撤掉已经写好的正文；ADR 0006 改成了正文先提交、结算随后。

## 决定

直接采用后者。叙事一轮正常结束就提交正文（`narrative/committed`，revision 加 1），然后把这一版的结算排进这一局的后台队列。结算失败只记 `settlement/failed`，正文不受影响。

为了让下一轮叙事看到最新状态，叙事开新一轮前最多等上一轮结算 120 秒；等不到就照常开始，下一版正文提交时上一版结算作废，迟到的结果因版本不符被拒绝。

## 后果

- 结算失败时玩家看得到：线索板显示失败原因和「重新结算」。只能重试最新一版。
- 被取消或出错的叙事轮次不提交，也不结算。
