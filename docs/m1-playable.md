# M1 能玩

> 2026-11-05，DSH 0.2.1-rc.5，Node 26.7.0，Windows 11。

## 结论

M1 的功能都已做完，并用假模型在网页里从开局一直玩到结案（S，100 分）。完成标准两条：

| 完成标准 | 状态 |
|---|---|
| 领域层单测覆盖四道校验 | 完成：`pnpm test` 55 条全过，四道校验各有该拦和不该拦的用例，另有信息隔离、事件日志重放、计分的测试 |
| 真人从头到尾破一次案 | **待做**：要接真模型，本机还没有保存 DeepSeek 密钥。步骤见下面的「用真模型玩」 |

M0 留下的第 3 项「缓存命中的真实数值」同样要等真模型：玩一局后跑 `pnpm stats`，或看线索板底部的用量行。

## 做了什么

| 部分 | 位置 | 说明 |
|---|---|---|
| 案卷「退潮之前」 | `cases/ebb-tide/case.json` | 4 个人物、6 个地点、12 条线索（2 条是干扰项）；证据链 4 环、2 道推理题 |
| 案卷 schema | `packages/domain/src/case/schema.ts` | zod 校验结构，另查引用完整性：地点相邻要双向、前置线索不能成环、地点都走得到 |
| 事件日志 | `packages/domain/src/game/log.ts` | 每局一个只追加的 JSONL，事件带 `branch` 与 `revision`；读取时跳过崩溃留下的半行 |
| 游戏状态 | `packages/domain/src/game/state.ts` | 由事件重放得到，程序是唯一写入者 |
| 四道校验 | `packages/domain/src/game/effects.ts` | schema → 规则（场景、前置线索、态度门槛、数值范围）→ 版本 → 原句；整批通过才原子写入 |
| 指认计分 | `packages/domain/src/game/scoring.ts` | 指认对 40 分，证据链 40 分，推理题 20 分；指认错人判 F |
| 按级别投影 | `packages/domain/src/game/projections.ts` | 线索板只给 L1；叙事和书记员拿 L2；真相（L3）只在结案后进线索板 |
| 叙事 | `packages/plugin/src/narrator.ts`、`prompts/narrator.md` | 挂在「雾港案卷」Agent 预设里：换系统提示词、关掉全部工具，每轮第一步前追加案情资料 |
| 书记员 | `packages/plugin/src/runtime.ts`、`clerk-tool.ts`、`prompts/clerk.md` | 每局一个后台会话，只有 `submit_effects` 一个工具；被驳回时按意见改正，最多 3 次 |
| 线索板 | `packages/client/client.js` | 右侧栏页签：时间、地点、本轮新发现、线索、口供、人物态度、地点、指认表单、结案复盘、用量 |
| 开发用假模型 | `packages/plugin/src/fake-llm.ts` | 不联网，扮演叙事和书记员，用来走通流程、调界面 |

一轮的流程：玩家输入 → 叙事插件等上一轮结算落定，按当前状态追加案情资料 → 叙事流式写正文 → 轮次正常结束时提交正文（revision 加 1）→ 结算排进这一局的后台队列 → 书记员调用 `submit_effects` → 四道校验通过就写入，线索板下一次轮询时更新。

## 怎么跑

| 命令 | 作用 |
|---|---|
| `pnpm web` | 用真模型玩 |
| `pnpm web:fake` | 默认模型换成不联网的假模型 |
| `pnpm test` | 领域层单测 |
| `pnpm stats` | 每局的轮数、结算情况、用量和缓存命中率 |

启动后终端会打出带 `token` 的地址，用浏览器打开它（第一次打开时种下登录 cookie）。

### 用真模型玩

1. `pnpm web`，打开终端里带 `token` 的地址。
2. 「设置 → 模型」里保存 DeepSeek 密钥。
3. 左侧工作区「雾港案卷」右边的加号新建会话。模式默认就是「雾港案卷」；模型选 DeepSeek 的任一模型。
4. 右上角打开右侧栏，选「线索板」，点「开始调查」。
5. 在对话框里行动：去哪、看什么、问谁、出示什么。线索板会记下发现。想好了在线索板上「指认凶手」。

书记员默认跟叙事用同一个模型。想让书记员用便宜的模型，启动前设 `CASEBOOK_CLERK_PROVIDER` 和 `CASEBOOK_CLERK_MODEL`。

### 假模型怎么玩

假叙事按字面规则写正文：输入里提到地点就走过去；提到线索的关键词、且发现条件满足，就把线索内容写出来；说「别怕」「保证」之类的话，在场的人态度加 1。输入里带「【测试：书记员驳回】」时，书记员第一次故意引错原句；带「【测试：书记员不提交】」时，这一轮结算失败，可以在线索板上点「重新结算」。

## 验证记录

假模型下完整玩了一局（9 轮），覆盖了以下情况：

- 开局：会话自动改名，线索板从「开始调查」进入对局。
- 同一轮里先移动再发现两条线索；前置线索在同一次提交里先发现也算。
- 证词线索要说话人态度达标：同一轮先安抚（态度 +1）再开口，通过。
- 书记员第一次引错原句：日志里有一条 `settlement/rejected`（规则错加原句错），改正后通过，`clerk/finished` 记 2 次尝试。
- 书记员不提交：催一次仍不提交，线索板显示失败和「重新结算」，点了以后结算成功。
- 中途重启 DSH：对局从事件日志原样恢复，书记员会话从存档恢复。
- 指认何慎之，出示四环证据，两题全对：S，100 分，真相复盘能展开。
- 结案后再说话：叙事只简短回应，不再提交正文。

DSH 会话日志核对过：叙事的系统提示词是 `prompts/narrator.md`，没有任何工具；每节资料（开局资料、地点资料、人物档案）只追加一次。书记员只有 `submit_effects` 一个工具。

## 已知问题与后续

- 书记员会话一直追加不压缩。一局 30–80 轮够用，压缩放到 M3 和案件版摘要一起做。
- DSH 的「工作目录」运行时上下文是必需项，`suppressRuntimeContext()` 关不掉，叙事第一轮会多一条工作区路径。对游戏没有影响。
- 结算失败后只能重试最新一版；下一轮正文提交后，上一版的失败不再能重试（正文先提交，ADR 0002）。
- 人物在 M1 里不走动，按地点算「见过谁」；M2 的案件日程会让人物移动。
- 回退、带意见重写、泄底扫描、参谋建议都在 M2。

## 踩到的坑

- 预设里的子插件由另一套加载逻辑直接 `import(name)`：Windows 上写 `D:/…` 会被当成 `d:` 协议，导入失败，界面只报「never started」。改成 `file://` URL 就好（`scripts/web.ts`）。
- 网页上点「选择工作区」会在桌面弹出系统选目录对话框。插件启动时自己登记了「雾港案卷」工作区（`.dsh-home/casebook/workspace`），玩家不用再选目录。
- DSH 的会话日志是多帧 zstd，`zlib.zstdDecompressSync` 只解第一帧；要按帧拆开逐个解。
